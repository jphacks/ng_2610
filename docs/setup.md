# Nigeyo setup and demo procedure

## Requirements

- macOS with Xcode 27.1 and an iPhone on iOS 27.0 or later.
- Node.js 24 (team baseline; 22 also works).
- Approved wallpapers are committed PNGs; no image renderer is needed.

## 1. Signing (once per Mac)

```sh
cp nigeyo-ios/Local.xcconfig.example nigeyo-ios/Local.xcconfig
# edit DEVELOPMENT_TEAM and, on a personal Mac, BUNDLE_ID_SUFFIX (e.g. .alice)
```

- The presentation iPhone uses an empty suffix, which gives `jp.nigeyo.hackathon`. Fix the bundle ID before you configure the shortcuts. Reinstalling or changing the ID means re-selecting the app in the notification automations.
- `Local.xcconfig` is git-ignored. Never commit the team or a personal bundle ID.
- Targets: `Nigeyo` (app), `NigeyoLiveActivity` (WidgetKit extension, `<app id>.LiveActivity`) and `NigeyoTests`. No App Group is used.

## 2. Mac server

```sh
npm ci
npm run demo:prepare      # live 551 → fixtures/demo, validates wallpapers, manifests, copies language packs into the iOS bundle
npm run demo:server       # http://127.0.0.1:8788
```

In another terminal:

```sh
npm exec --cache /private/tmp/nigeyo-npm-cache --yes --package cloudflared -- cloudflared tunnel --protocol http2 --url http://127.0.0.1:8788
```

Open <http://127.0.0.1:8788>, paste the `https://….trycloudflare.com` origin and press **登録**, then copy the pairing string.

```sh
npm run demo:preflight    # Node, port, fixture, languages, pictograms, checksums, signed shortcuts, public reachability
npm test                  # server tests (node:test)
```

## 3. iPhone

1. Run the `Nigeyo` scheme from Xcode on the iPhone and keep the debugger attached for the main demo.
2. Complete onboarding: language → home/school → four slots → lock-screen setup. Allow notifications.
3. Go to Settings → **発表用デモ接続**, paste the pairing string and press **接続する**. The PC shows the device, language and heartbeat.
4. In onboarding or Settings → Lock screen, follow the four steps: allow notifications → add both shortcuts → enable automation → test each wallpaper. The signed **Nigeyo 地震** and **Nigeyo 津波** files and their images are bundled in the app: adding them needs no Mac server, pairing, or public URL. Use the iOS file handoff to Shortcuts (or save to Files and open the file). Enable both imported automations and reselect the installed Nigeyo; see [shortcuts.md](shortcuts.md). Disable the old catch-all automation. PC demo notifications still use the connection above.
5. With multiple iPhones connected, select the intended phone on the PC. Each has its own run, ACK and retry state; a different browser window can select another phone. Lock the iPhone. The PC must show *ready* (heartbeat within 15 s, notifications `authorized`, matching resource and language versions).

## 4. Demo

1. Press **地震デモ開始** (earthquake only), **津波デモ開始** (tsunami only: tsunami wallpaper, `TSUNAMI_TEST`, straight to the tsunami guide) or **地震 → 津波デモ開始** (earthquake, then the tsunami follow-up).
2. Expected status sequence: 準備中 → 送信中 → 端末で通知予約済み. *端末の応答なし（予約成否不明）* means no ACK after one resend. It does not mean the notification failed.
3. For `earthquake-tsunami`, press **津波訓練通知を送る** once the protect screen is showing. It is never linked to the shaking-confirmation button.
4. To end, use the app's **訓練を終了**, restore the wallpaper by hand, and press **表示をリセット** on the PC.

The operator details panel records `live-api` / `last-good` / `fixture`, the API failure reason, the source event ID and issue time, and the send and ACK times. Logs are written to `artifacts/demo/YYYY-MM-DD.jsonl`.

## 5. Swift tests

```sh
cd nigeyo-ios
xcodebuild -scheme Nigeyo -destination 'platform=iOS Simulator,name=iPhone 17' CODE_SIGNING_ALLOWED=NO test
```

## Data

- `nigeyo-ios/Nigeyo/Resources/evacuation-sites.json` is generated by `npm run evacuation:import -- mergeFromCity_2.csv --retrieved YYYY-MM-DD`. Its source, checksum and counts are in `assets/evacuation-sites.manifest.json`.
- Adding a language: drop `assets/languages/<bcp47>.json`, then run `npm run languages:validate` and `npm run languages:prepare`. No Swift change is needed. Installed apps fetch it from Settings → 言語パッケージを更新.

## Failure handling (spec §18.2)

| Failure | What happens / what to do |
| --- | --- |
| Earthquake API down or slow | 3 s timeout, then last-good, then fixture. The source is shown truthfully in the operator panel. |
| iPhone disconnected / heartbeat stale | Start is disabled. Unlock the phone, reopen the app, check Xcode. |
| ACK lost | One resend with the same runId. No double notification. |
| Wallpaper hosting unreachable | Notification-time wallpaper changes still work: each shortcut has its own embedded image. Initial shortcut download requires a connection ([shortcuts.md](shortcuts.md)). |
| Live Activity off or failed | The app, notification and wallpaper continue. It is not reported as a success. |
| Venue network down | Run the in-app drill. Do not claim a live PC connection. |

## Multiple devices and local-only wallpaper changes

Connect both phones with the pairing string. Select one phone and start an earthquake demo, then select the other and start a tsunami demo immediately (or use two browser windows). Commands never broadcast. Two simultaneously connected phones require an explicit `deviceId` on `POST /api/demo/run`, `/api/demo/tsunami`, `/api/demo/reset` and `/api/tsunami/observe`. `GET /api/status` lists `devices`; add `?deviceId=<id>` to inspect one. The id is connection-specific and changes after reconnecting; stale targets return 404. An omitted target is accepted only with exactly one connected phone.

552 target-area selection and observers are per connection. Configure each phone separately. These are explicit demo actions and the existing 552 observation feature, not automatic location-based 551 alert delivery. No GPS data or app UI changes are introduced. Keep the Xcode debugger attached as before.

`/public/assets/wallpaper.png` returns 410. Only immutable per-hazard PNG downloads remain. Downloading the two signed shortcuts also installs their images into Shortcuts on the phone, with no image-server access at runtime. Reinstall the shortcuts to update their images.
